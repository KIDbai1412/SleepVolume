# 睡眠音量（SleepVolume）

一个只管**系统媒体音量**的 Android 小工具，用来在睡前制造「放一阵 → 静一阵 → 更轻地回来」的循环。

它**不**控制任何播放器的播放/暂停，所以：

- 不需要无障碍服务、不需要通知使用权、不需要 root
- 对 B 站、腾讯视频、酷狗、网易云、播客、有声书全都一样生效
- 视频不会暂停，不丢播放位置，回来时不会触发贴片广告

## 它怎么工作

```
音量 8 ──── 播放 5 分钟 ──── 淡出 8 秒 ──→ 静音
                                              │
                                           静默 5 分钟
                                              │
音量 6 ←──────── 淡入 8 秒 ───────────────────┘
   │
   └── 再来一轮，直到：轮数用完 / 总时长到顶 / 音量降到 0
```

每轮音量 = 起始音量 − (轮数 − 1) × 每轮降低档数。
正常结束时保持静音（可关，关掉就恢复起始音量）；手动点「停止」一律恢复起始音量。

## 怎么编出 APK

### 路线 1：GitHub Actions（不需要装任何东西）

1. 在 GitHub 新建一个空仓库
2. 把这个目录里的所有文件传上去（网页上传也行，但 `.github` 文件夹要用 git 推，网页拖拽可能丢）
3. 打开仓库的 **Actions** 标签页，等 `Build APK` 跑完
4. 进这次运行，页面底部 **Artifacts** 里下载 `SleepVolume-debug.zip`，解压得到 `app-debug.apk`
5. 传到手机安装

> 工作流文件：`.github/workflows/build.yml`，用的是 GitHub 官方 runner 自带的 Android SDK，不需要额外配置。

### 路线 2：Android Studio

1. 装 Android Studio，打开 `SleepVolume` 这个目录
2. 如果提示缺 Gradle Wrapper，按提示让它补齐（或用自带 Gradle 同步）
3. `Build → Build Bundle(s) / APK(s) → Build APK(s)`
4. 产物在 `app/build/outputs/apk/debug/app-debug.apk`

### 路线 3：已经装了 Android SDK 的命令行

```bash
gradle :app:assembleDebug
```

要求：JDK 17、`compileSdk 34` 的 platform、build-tools。

## 装上之后，小米手机上必须做的三件事

不做的话，循环跑几分钟就被系统掐掉。

| 位置 | 设置 |
|---|---|
| 设置 → 应用设置 → 应用管理 → 睡眠音量 → **省电策略** | 改成「**无限制**」 |
| 同页 → **自启动** | 允许 |
| 最近任务列表 → 长按「睡眠音量」卡片 → 加锁 | 上锁（防止一键清理清掉） |

应用内有个「关闭电池优化」按钮，点了顺手同意一下，但它**不能替代**上面的「省电策略」——小米自己那一层更狠。

另外，Android 13 以上会弹通知权限，**必须允许**，否则前台服务通知看不到，服务也可能被判定为异常。

## 怎么用

1. 先用音量键把媒体音量调到你习惯的档位（比如 8/15）
2. 打开 B 站 / 腾讯视频 / 酷狗，正常播放
3. 回到「睡眠音量」，点**开始**
4. 锁屏，把手机扣过去

想在后台常驻看到进度，下拉通知栏，有一条「睡眠音量循环」，点里面的「停止」可以随时中止。

### 用之前必须先解决的一件事：锁屏后别让播放器自己停

这个应用只调音量，**播放器停没停它管不了**。而 B 站、腾讯视频默认锁屏就暂停，这样你听到的会是「一开始就没声」，而不是「放 5 分钟再静」。

去各自的设置里打开：

- **B 站**：设置 → 播放设置 → 允许后台播放 / 锁屏后继续播放
- **腾讯视频**：设置 → 播放设置 → 后台播放（部分内容需要会员）
- **酷狗 / 网易云**：默认就支持后台播放，一般不用管

开完之后先手动验一次：播放中按锁屏键，等 10 秒，声音还在，才算准备好。

## 参数

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| 单轮播放时长 | 1–30 分钟 | 5 | 这一轮保持正常音量的时间 |
| 静默时长 | 1–30 分钟 | 5 | 完全静音的时间 |
| 每轮降低 | 1–95% | 34% | 按**起始音量**算固定步长，每轮减同一个数 |
| 最多循环轮数 | 1–12 轮 | 6 | 上限；音量先降到 0 会提前结束 |
| 淡出时长 | 0–30 秒 | 8 | 变安静用多久，0 = 瞬间断掉 |
| 淡入时长 | 0–30 秒 | 8 | 恢复播放用多久，0 = 瞬间跳出 |
| 总时长上限 | 0–120 分钟 | 不限 | 0 = 只用轮数控制 |

### 「每轮降低」是怎么算的

**固定步长，不是复利。** 点开始的那一刻，用当时的音量算一次：

```
步长 = round(起始音量 × 百分比)，最少 1 档
```

之后每一轮都减这同一个数，跟当前音量无关。

举例：起始 40 档、设 34% → 步长 = 13.6 → 取整 14 → 40 → 26 → 12 → 0，**3 轮见底**。

手机上满格通常只有 15（部分机型 25 或 30），所以实际是：起始 8 档、34% → 步长 2.72 → 取整 3 → 8 → 5 → 2 → 0，同样是 3 轮。

之所以要取整，是因为 Android 的媒体音量是**整数档**，没有半档。百分比填得再细，最终也只能落在整档上。

界面预览会把真实轨迹和取整过程都打出来，不用心算：

```
音量走向：8 → 5 → 2 → 0（满格 15）
每轮固定降 3 档（起始 8 × 34% = 2.7，取整为 3）
共 3 轮，约 30 分钟。
```

### 淡出和淡入是分开的两个参数

四种组合都能配，体验差别很大：

| 淡出 | 淡入 | 效果 |
|---|---|---|
| 0 | 0 | 双向硬切：声音瞬间消失，回来瞬间跳出。最接近「视频突然卡住」那个感觉 |
| 0 | 8 秒 | 断得干脆，回来慢慢升起。**睡前通常最好用**：断的时候不吓你，回的时候不打扰 |
| 8 秒 | 0 | 慢慢没声，回来突然出现。容易在恢复那一下被吓到，一般不建议 |
| 8 秒 | 8 秒 | 两头都柔。最温和，但也最不像你描述的那个「卡顿」 |

两个都设 0 时，界面预览会明确提示「双向硬切」。

## 已知限制 / 可能会踩的坑

- **这是应用级音量，不是按应用分音量**。调的是 `STREAM_MUSIC`，所以闹钟之外的所有媒体一起被调。
- **媒体音量归零不影响闹钟和来电铃声**——它们走的是 `STREAM_ALARM` / `STREAM_RING`，不会被静音，早上照样响。
- **勿扰模式下可能改不动音量**。代码里吞掉了异常，不会崩，但会静默失败。
- **蓝牙耳机**如果开了「绝对音量」，音量档位可能是耳机那侧的，表现会略有不同。
- **国产 ROM 杀后台**是最大的变量。三家（小米 / 华为 / OPPO）各有各的开关，小米的见上面。
- **不要在开着导航的时候用**——导航语音也走媒体流。
- 本工程**没有在本机编译验证过**（写代码的机器上没有 Android SDK）。如果 `gradle sync` 或编译报错，把错误贴出来即可，一般是版本号或某个属性写法的问题，很好修。

## 代码结构

```
app/src/main/java/com/sleepvolume/
├── MainActivity.java      设置界面 + 实时状态刷新（500ms 轮询静态状态）
├── SleepLoopService.java  前台服务：阶段状态机、音量淡入淡出、通知
├── LoopSettings.java      六个参数，存 SharedPreferences
└── LoopState.java         服务和界面之间的只读运行时快照
app/src/main/res/layout/activity_main.xml   单页深色界面
```

服务里的三个阶段常量：`PH_PLAY → PH_FADE_OUT → PH_SILENT → PH_FADE_IN → PH_PLAY`，
由一个 120–400ms 的 `Runnable` 驱动，时间基准是 `SystemClock.elapsedRealtime()`（不受系统时间修改影响）。
